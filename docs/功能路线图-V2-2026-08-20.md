# 工作日志台（geminix）功能扩展方案 V2

> 文档版本：v2.0　日期：2026-08-20
> 前置：V1 四梯队方案（2026-08-10）已落地一/二/三梯队 + 全局搜索 + Markdown 批量导入
> 服务器已部署 milvus-standalone v3.0-beta（含 etcd/minio），当前代码未接入

## 〇、总览

以「导入之后怎么办」为起点，分三个梯队推进：先补数据维度与体验（P0），
再接入已部署的 Milvus 做 AI 检索（P1，承接 LangChain/Milvus 规划），最后做沉淀与协作（P2）。

| 梯队 | 主题 | 核心收益 | 建议投入 |
|------|------|----------|----------|
| P0 | 项目维度 + 导入增强 + 暗色模式 | 多项目日志可归类、导入不再丢信息 | 3 个小功能，单周内 |
| P1 | Milvus AI 检索 + 问答 + 令牌/推荐 | 个人知识库可语义搜索、AI 问答 | 中等，分 2 个子阶段 |
| P2 | PWA/移动端 + 自动周月报 + 年度回顾 + 协作 | 随手记、自动沉淀、多人可选 | 穿插迭代，按需 |

## 一、P0：立刻做，性价比最高

### 1.1 项目维度（强烈建议第一个做）

| 项目 | 内容 |
|------|------|
| 说明 | 日报/问题新增「项目」字段，导入/新增时可选，列表、统计、周月报按项目过滤。解决「导入的 ai-recruit 日志混在一起无法区分」的现状 |
| 技术点 | `report` 表加 `project` VARCHAR(32)（可空=未分类）；`issue` 表同；`ReportReq`/`ImportReq` 加字段；列表接口加 `project` 过滤参数；周/月报导出按项目分组；前端新增/编辑弹窗加项目选择（内置常用项目 + 自定义） |
| 落库 | 无需新表；存量数据 project 置空，标签筛选仍可用 |
| 验收 | 导入 ai-recruit 日志时选「ai-recruit」，列表可按项目筛；周报按项目分组展示 |

### 1.2 导入增强（补足 V1 导入的短板）

| 项目 | 内容 |
|------|------|
| a. 导入时可选标签/项目 | 不再固定「导入」标签，弹窗加标签/项目下拉，导入即归类 |
| b. 非日期文件处理 | `MEMORY.md` 等非日期文件目前只能跳过；改为「可选导入为问题(issue)」或「手动指定日期导入为日报」，弹窗内预览可调 |
| c. 增量导入提示 | 重复日期导入时预览阶段就标黄（已有），确认前可见，避免入库后才发现 skip |
| 技术点 | 前端 ImportModal 扩展；后端 ImportService 支持指定 date/tags/project 覆盖；`issue` 复用现有表 |
| 验收 | 全选 memory 目录文件，MEMORY.md 可显式选择导入方式；重复文件预览标黄 |

### 1.3 暗色模式（V1 遗留，工作量最小）

| 项目 | 内容 |
|------|------|
| 说明 | CSS 变量已全局定义（--bg/--card/--text 等），只需补暗色变量 + `data-theme` 切换 + localStorage 记忆 |
| 技术点 | 前端加 `ThemeToggle` 组件（顶栏），`index.css` 补 `[data-theme="dark"]` 变量集；ECharts 主题跟随 |
| 验收 | 顶栏切换明/暗，刷新保持 |

## 二、P1：Milvus AI 检索与问答（承接已部署的向量库）

> 服务器已有 milvus-standalone，这是「个人学习系统」的核心价值所在 —— 把日报、问题、
> 导入的 Obsidian/日志笔记全部向量化，语义检索 + AI 问答。

### 2.1 知识库入库管道（子阶段 A）

| 项目 | 内容 |
|------|------|
| 说明 | 新增 Python AI 服务（或 Java 直连 Milvus）：日报/问题/导入文档 → 分块 → embedding → 写入 Milvus collection；日报增删改时同步更新向量 |
| 技术点 | 新增 `ai-service`（FastAPI，复用 ai-recruit 同款 deepseek-v4-flash + embedding）；collection `geminix_docs`（维度视 embedding 模型定，COSINE + IVF_FLAT）；用 `report.id`/`issue.id` 做主键映射，删除时同步清理 |
| 衔接 | 导入功能完成后自动触发向量化；存量数据启动时全量回填一次 |
| 验收 | 导入 10 篇日志后，语义搜索能命中相关内容 |

### 2.2 语义搜索 + AI 问答（子阶段 B）

| 项目 | 内容 |
|------|------|
| a. 语义搜索 | 现有全局搜索（SQL LIKE）升级为「关键词 + 语义」双路，搜索框下拉混排 |
| b. AI 问答 | 顶栏/侧栏加问答入口：基于个人库 RAG，回答「我 8 月做过哪些招聘系统的事」「N+1 问题怎么解决的」等；引用来源（对应日报/问题卡片，点击跳转） |
| 技术点 | 前端搜索组件改造 + 问答面板；后端 `SearchController` 增加语义接口、新增 `AskController`（调 ai-service） |
| 验收 | 搜索「缓存击穿」能召回语义相关的历史问题；问答带来源引用 |

### 2.3 令牌与推荐（V1 第四梯队遗留）

| 项目 | 内容 |
|------|------|
| a. Refresh Token | 双 token：access 2h + refresh 7d（Redis 白名单），前端静默刷新，登出吊销 |
| b. 搜索热词缓存 | Redis ZINCRBY，列表页 TOP10 |
| c. 问题相似推荐 | 标签 + 关键词相似度，问题编辑弹窗底部推荐 3 条历史问题 |
| 技术点 | JwtAuthInterceptor 改造 + 前端拦截器；StatsService 复用；Jaccard/分词相似度 |

## 三、P2：沉淀与协作（按需穿插）

| 功能 | 说明 | 技术点 |
|------|------|--------|
| PWA + 移动端 | 桌面图标 + 离线壳 + 窄屏适配 | vite-plugin-pwa；响应式断点已预留 |

## 四、实施顺序建议

```
P0.1 项目维度 ──→ P0.2 导入增强 ──→ P0.3 暗色模式
        ↓
P1.1 向量入库（ai-service + Milvus）──→ P1.2 语义搜索 + AI 问答
        ↓
P1.3 Refresh Token / 热词 / 相似推荐 ──→ P2 各项按需
```

建议节奏：P0 一次提交做完（前端 + 后端各一个 commit）；P1 拆两个子阶段，每阶段一个 commit；
每阶段完成后跑 `mvn compile` / `vite build` 验证再进下一阶段。

## 五、依赖与风险

| 项 | 说明 |
|----|------|
| Milvus 版本 | 服务器 milvus v3.0-beta，Java SDK 选匹配版本（或走 Python ai-service 直连 REST） |
| embedding 模型 | 需确定（bge-m3 中文 / text-embedding 系列），决定 collection 维度 |
| 存量回填 | 首次接入需全量向量化，量小（当前 13 条日报）无压力 |
| 项目字段兼容 | `project` 可空，旧数据不受影响；周月报导出需兼容 null |
