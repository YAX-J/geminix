| # | 差距                              | 证据                                                                                                      |

| 1 | `report` / `issue` 表无 `user_id` | `backend/sql/init.sql:16-40`（无 user_id 列）                                                             |

## 二、分阶段方案

### 阶段一：多用户数据隔离（地基，优先）✅ 已完成

**目标**：每个用户只见自己的日报/问题/标签，越权访问返回 404。

**表结构**（迁移脚本，Alembic 式手工 SQL）：
- `report` 加 `user_id BIGINT NOT NULL DEFAULT 0` + `KEY idx_report_user (user_id)`
- `issue` 加 `user_id BIGINT NOT NULL DEFAULT 0` + `KEY idx_issue_user (user_id)`
- `tag` **保持全局**（D3：公共字典，不加 user_id）
- 清空演示数据（D4）：移除 init.sql 中 report/issue 的演示 INSERT

**后端**：
- 新增 `UserContext`（ThreadLocal 持有 userId），`JwtAuthInterceptor` 在 setAttribute 同时写入 UserContext，`afterCompletion` 清理
- 所有 report/issue 查询/写/删统一追加 `user_id = UserContext.getUserId()`；`getById` 改为 `eq(id).eq(user_id)`
- `tag` 保持全局不变（阶段二再加 ADMIN 管理权限）
- 越权统一返回 404（不暴露资源存在性）

**前端**：本阶段无感知（接口签名不变），仅登录/注册后数据自动隔离。

**验收**：注册两个账号，各自写日报/问题，互不可见；用 A 的 token 请求 B 的 report id 返回 404。

---

### 阶段二：角色权限（ADMIN / AUTHOR / READER）✅ 已完成

**目标**：三角色权限分级 + 管理端用户管理。

- `app_user` 加 `role VARCHAR(16) NOT NULL DEFAULT 'AUTHOR'`（存量 admin 置 `ADMIN`）
- 开放注册：注册请求携带角色（`AUTHOR` / `READER`，默认 `AUTHOR`），`ADMIN` 不可通过注册获得
- 后端新增 `@RequireRole("ADMIN")` 注解 + 拦截器校验；写接口（新增/改/删）要求 AUTHOR 及以上，READER 只读
- `tag` 管理（增删改）收敛为 ADMIN 权限（全局共享字典）
- 新增 `UserController`（管理端）：`GET /api/users`（ADMIN 专用）、改角色、禁用/启用、重置密码
- `InitAdminRunner` 调整：首次启动建 admin（role=ADMIN）
- 前端：新增「用户管理」页（ADMIN 可见）；注册页角色选择；按钮级权限（READER 隐藏新增/编辑/删除）

**验收**：READER 登录后无编辑/删除入口；ADMIN 可在用户管理页改角色；越权调用写接口返回 403。

---

### 阶段三：Markdown + 代码高亮 ✅ 已完成

**目标**：日报任务、问题描述/方案支持 Markdown 渲染（含代码块高亮），贴合「代码学习记录」场景。

- 前端引入 `markdown-it` + `highlight.js` + `DOMPurify`（防 XSS）
- 编辑弹窗提供「编辑 / 预览」切换；卡片内渲染预览（纯文本降级）
- 后端无需改动（存原文，渲染放前端）

**验收**：日报/问题里贴 ```java / ```sql 代码块，卡片高亮显示；恶意 `<script>` 被 DOMPurify 过滤。

---

### 阶段四：全局搜索 ✅ 已完成

**目标**：跨日报 + 问题联合搜索（当前 keyword 仅搜日报）。

- 后端新增 `GET /api/search?keyword=xxx`，联合查 report + issue（title/description/solution/tasks），按 user_id 隔离
- 前端顶栏搜索框接入，结果分「日报 / 问题」两组展示
- 起步 LIKE，后续平滑升级 MySQL FULLTEXT / Milvus 语义搜索（服务器已有 Milvus v3.0）

**验收**：搜一个关键词能同时命中日报与问题；不同用户搜索结果隔离。

## 三、已确认决策（2026-08-18）

| #  | 决策         | 结论                                                                                               |
|----|--------------|----------------------------------------------------------------------------------------------------|
| D1 | 角色体系     | **ADMIN / AUTHOR / READER 三角色**（READER 只读、AUTHOR 可写、ADMIN 全部+管用户）                  |
| D2 | 注册策略     | **开放注册，注册时可选 AUTHOR / READER**（默认 AUTHOR；ADMIN 不可自注册，仅由 ADMIN 在管理页提升） |
| D3 | 标签归属     | **全局共享标签**（tag 表不加 user_id，公共字典；管理需 ADMIN 权限）                                |
| D4 | 存量演示数据 | **清空重来**（init.sql 移除 6 日报 + 8 问题演示数据，仅保留表结构 + 默认五类标签 + admin 账号）    |
