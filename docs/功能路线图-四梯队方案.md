# 工作日志台（geminix）功能路线图 · 四梯队方案

> 技术栈：Java 21 + Spring Boot 3.3.5 + MyBatis-Plus + MySQL + Redis（后端）
> Vue 3.4 + Vite + Pinia（前端，Element 风格自定义组件）
> 文档版本：v1.0　日期：2026-08-10

---

## 〇、总览

以「性价比优先」为原则，将功能演进分为四个梯队：先补齐高频刚需（第一梯队），
再增强核心价值（第二梯队），随后迈向多用户（第三梯队），最后打造技术亮点（第四梯队）。

| 梯队 | 主题 | 核心收益 | 建议投入 |
|------|------|----------|----------|
| 🚀 第一梯队 | 立刻做，性价比最高 | 补齐编辑/导出/收藏/安全四大高频刚需 | ✅ 已完成 |
| 🏗 第二梯队 | 增强核心价值 | 提醒、统计、标签体系、Excel 导出 | ✅ 已完成 |
| 👥 第三梯队 | 多用户与体验 | 数据隔离、角色权限、Markdown、暗色、PWA | 2-3 个迭代 |
| 💡 第四梯队 | 技术亮点 | 热词缓存、相似推荐、refresh token | 穿插迭代 |

## 一、第一梯队：立刻做，性价比最高

### 1.1 日报编辑 / 删除

| 项目 | 内容 |
|------|------|
| 说明 | 前端卡片上「编辑」支持打开弹窗回填并保存；「删除」二次确认后移除 |
| 技术点 | 前端弹窗复用 `ReportModal`（编辑模式预填）；后端 `PUT /api/reports/{id}`、`DELETE /api/reports/{id}` |
| 现状 | ✅ 已实现（后端 PUT/DELETE + 前端编辑弹窗/删除按钮均已就绪），无需改动 |
| 验收 | 卡片点编辑 → 弹窗回填原内容 → 保存后卡片刷新；点删除 → confirm → 列表移除 |

### 1.2 周报 / 月报导出

| 项目 | 内容 |
|------|------|
| 说明 | 顶栏「导出周报」可用；新增「导出月报」，按周/月聚合日报与问题生成 Markdown 文件 |
| 技术点 | 后端 `ReportService.exportWeekly / exportMonthly` 聚合日报（按天分组）+ 问题（含方案）生成 Markdown；文件以 `Content-Disposition` 下载 |
| 现状 | 周报 ✅ 已实现；**月报 ❌ 本次新增**：`GET /api/reports/export/monthly?date=yyyy-MM-dd` + 顶栏按钮 |
| 验收 | 顶栏分别导出周报/月报，下载 `.md` 文件内容含「本周/本月工作」「问题与方案」两节 |

### 1.3 问题多方案 + 收藏

| 项目 | 内容 |
|------|------|
| 说明 | 一个问题可积累多个解决方案（标记一个为「最佳」）；常见问题可收藏并置顶展示 |
| 技术点 | `issue` 表新增 `solutions JSON`（元素 `{content, best}`）、`favorite TINYINT(1)`；列表排序 `favorite DESC` 置顶；后端 `PATCH /api/issues/{id}/favorite` 切换收藏；保留原 `solution` 字段兼容旧数据（best 方案自动同步） |
| 现状 | ❌ 本次新增（表结构 + 后端 CRUD/排序 + 前端多方案表单/卡片收藏） |
| 验收 | 新增问题可录入多个方案并标记最佳；卡片展示最佳方案高亮、其余可展开；⭐ 可收藏，收藏项置顶 |

### 1.4 登录防爆破

| 项目 | 内容 |
|------|------|
| 说明 | 连续错误密码 5 次锁定 10 分钟，期间禁止登录 |
| 技术点 | Redis 计数器：`INCR worklog:login:fail:{username}`，首次失败设置 `EXPIRE 600s`；登录成功清除；锁定期间读取计数拒绝登录并提示剩余时间 |
| 现状 | ✅ 核心已实现（Redis incr + 过期键）；**本次增强**：锁定提示携带剩余倒计时、计数解析健壮性 |
| 验收 | 错误密码第 5 次后返回 429 锁定提示；10 分钟后自动解锁（Redis 键过期）；正确登录后计数清零 |

## 二、第二梯队：增强核心价值（✅ 已实施，2026-08-10）

### 2.1 日报提醒（每天 18:00）

- 后端：`DailyReportReminderTask` `@Scheduled(cron = "0 0 18 * * ?")` 检查当日未写日报则写入 Redis 提醒标记 `worklog:remind:{date}`（TTL 至当日 24:00）；`GET /api/reminders/today-status` 返回 written/remind/streak；日报写入后自动清除当日标记
- 前端：`ReminderBanner` 顶部提示条「今天还没写日报哦」+「＋ 去记录」快捷入口，当天可关闭（localStorage 记忆），写完自动收起
- 注意：已启用 `@EnableScheduling`；多实例部署时建议加 Redis 分布式锁防重复触发

### 2.2 连续打卡统计（streak）

- `GET /api/stats/streak`：按 `report_date` 去重集合从今天（今天未写则从昨天）往回计数连续天数
- 前端：热力图下方数据概览区展示「🔥 已连续打卡 N 天」（mock 模式本地计算，API 模式调接口）

### 2.3 问题统计图表（ECharts）

- 后端：`GET /api/stats/issue-dist` 类型全量分布（饼图）、`GET /api/stats/issue-trend?days=14` 每日新增/解决（折线图），均走 Redis 缓存并随写操作失效
- 前端：引入 `echarts@6.1.0`，`OverviewPanel` 新增「问题类型分布」环形饼图 +「问题趋势」双折线图；数据变化自动刷新，窗口缩放自适应

### 2.4 自定义标签

- `tag` 表独立（id / name / color / sort，name 唯一），后端 `GET/POST/PUT/DELETE /api/tags` 完整 CRUD
- 前端：`TagManageModal` 标签管理弹窗（新增/重命名/删除），顶栏「🏷 标签」与侧栏筛选区「管理 ›」入口；`stores/tags.js` 统一标签来源，日报/问题弹窗标签选项与侧栏筛选全部动态加载（mock 模式本地持久化自定义标签）

### 2.5 数据导出 Excel（EasyExcel）

- 后端：引入 `easyexcel@3.3.4`；`GET /api/reports/export/excel`（日报）、`GET /api/issues/export/excel`（问题），注解模型 `ReportExcelRow` / `IssueExcelRow` 输出 xlsx
- 前端：顶栏「导出 ▾」下拉整合 周报/月报（Markdown）/ 日报 Excel / 问题 Excel；mock 模式自动降级为带 BOM 的 CSV 下载（Excel 中文不乱码）

## 三、第三梯队：多用户与体验（规划）

### 3.1 数据按用户隔离

- `report` / `issue` 表新增 `user_id` 外键；所有查询强制追加 `user_id = 当前用户`
- JWT 已注入 `userId`，Service 层统一从请求上下文获取，杜绝越权

### 3.2 角色权限

- `app_user` 表加 `role` 字段（ADMIN / USER）；管理端可管理用户
- ADMIN 可查看全局统计/管理标签，USER 仅见自己数据

### 3.3 Markdown 支持

- 日报/问题描述支持 Markdown 渲染：前端引入 markdown-it + DOMPurify，卡片内渲染预览

### 3.4 暗色模式

- CSS 变量已全局定义（`--bg/--card/--text` 等），只需维护一套暗色变量 + `data-theme` 切换 + localStorage 记忆

### 3.5 移动端 / PWA

- Vite PWA 插件（vite-plugin-pwa）生成 manifest + Service Worker
- 响应式：窄屏时右侧面板隐藏（当前布局已预留断点），补全移动端操作入口

## 四、第四梯队：技术亮点（规划）

### 4.1 搜索热词缓存

- 搜索关键词写入 Redis `ZINCRBY worklog:search:hot`，列表页顶部展示 TOP10 热词
- TTL 定期重置，防止脏词堆积

### 4.2 问题相似推荐

- 按标签 + 关键词（分词/Jaccard 相似度）推荐「你可能遇到的问题」
- 在问题详情/编辑弹窗底部展示 3 条相似历史问题，提高方案复用率

### 4.3 Refresh Token 机制

- 登录签发 `access_token`（短效，如 2h）+ `refresh_token`（长效，如 7d，Redis 存白名单）
- access 过期后前端静默刷新，无需频繁重登；登出时吊销 refresh_token
- 当前 JWT 单 token 24h，升级为双 token 需改造 `JwtAuthInterceptor` 与前端拦截器
