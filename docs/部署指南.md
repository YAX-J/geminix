# 工作日志台（geminix）服务器部署指南（裸机 systemd 版）

> 适用：Linux 服务器（Ubuntu 20.04+ / CentOS 7+ / 云服务器均可）
> 架构：Spring Boot 3.3（Java 21）+ MySQL 8 + Redis + Nginx（静态托管 + API 反向代理）
>
> ⚠️ **当前主推 Docker 部署**（前后端已拆两仓库、走容器互联），本文档为裸机 systemd 备选方案，
> 首次部署请优先看 [`Docker部署指南.md`](./Docker部署指南.md)。

---

## 〇、架构一览

```
浏览器 ──> Nginx :80/443
             ├── /        → 前端静态文件（frontend/dist）
             └── /api/*   → 反向代理 → Spring Boot :8080
                                        ├── MySQL :3306（库 worklog）
                                        └── Redis :6379（缓存 / 登录防爆破 / 提醒标记）
```

---

## 一、服务器基础环境

```bash
# Ubuntu / Debian
sudo apt update && sudo apt install -y openjdk-21-jre mysql-server redis-server nginx git

# CentOS / Rocky
sudo yum install -y java-21-openjdk mysql-server redis nginx git
```

> JDK 21 是硬性要求（pom 的 `<java.version>21</java.version>`）；若发行版仓库没有
> JDK 21，可下载 Temurin：<https://adoptium.net/temurin/releases/?version=21>

启动并设置开机自启：

```bash
sudo systemctl enable --now mysql redis nginx
```

## 二、数据库初始化

```bash
sudo mysql -uroot -p
```

```sql
-- 先创建后端要用的账号（或直接用 root，生产建议独立账号）
CREATE USER 'worklog'@'localhost' IDENTIFIED BY '换成强密码';
GRANT ALL PRIVILEGES ON worklog.* TO 'worklog'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

导入表结构与演示数据（**覆盖全量，含 tag 表**）：

```bash
git clone https://github.com/YAX-J/geminix.git /opt/geminix
cd /opt/geminix
sudo mysql -uworklog -p < backend/sql/init.sql
```

> `init.sql` 会 `CREATE DATABASE IF NOT EXISTS worklog` 并 DROP 重建四张表（report/issue/app_user/tag）。
> 脚本顶部已带 `SET NAMES utf8mb4;`，中文默认值不会因客户端字符集报错。
> 生产环境想保留历史数据时，请改用手动 ALTER 增量迁移，勿直接执行全量脚本。

## 三、后端打包与部署

### 3.1 本地打包（或服务器上打包）

```bash
cd /opt/geminix/backend
mvn clean package -DskipTests
# 产物：backend/target/worklog-backend-0.1.0.jar
```

> 服务器若未装 Maven/JDK 21 工具链，可在本地 `mvn package` 后把 jar 传到服务器：
> `scp backend/target/worklog-backend-0.1.0.jar root@服务器IP:/opt/geminix/backend/`

### 3.2 生产配置（环境变量覆盖，不写死在 yml）

`application.yml` 中连接信息均可用环境变量覆盖，启动时注入：

| 环境变量 | 说明 | 示例 |
|----------|------|------|
| `DB_URL` | JDBC 地址（可选，默认 127.0.0.1:3306/worklog） | `jdbc:mysql://127.0.0.1:3306/worklog?...` |
| `DB_USERNAME` | 数据库账号 | `worklog` |
| `DB_PASSWORD` | 数据库密码 | `你的强密码` |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` | Redis 连接 | `127.0.0.1` / `6379` |
| `JWT_SECRET` | HS256 密钥（≥32 字节，生产必改） | 随机 32+ 位字符串 |
| `JWT_EXPIRE_HOURS` | token 有效期小时（默认 24） | `24` |

> 说明：`application.yml` 已预置 `${ENV:default}` 占位符（datasource / redis / jwt 三块均可被
> 环境变量覆盖），无需再改，直接打包即可。生产环境务必通过环境变量注入 `DB_PASSWORD` / `JWT_SECRET`。

### 3.3 systemd 托管（推荐，开机自启 + 崩溃重启）

```bash
sudo tee /etc/systemd/system/worklog.service > /dev/null <<'EOF'
[Unit]
Description=WorkLog Backend
After=network.target mysql.service redis.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/geminix/backend
ExecStart=/usr/bin/java -Xms256m -Xmx512m -jar /opt/geminix/backend/target/worklog-backend-0.1.0.jar
Environment="DB_URL=jdbc:mysql://127.0.0.1:3306/worklog?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true"
Environment="DB_USERNAME=worklog"
Environment="DB_PASSWORD=你的强密码"
Environment="REDIS_HOST=127.0.0.1"
Environment="REDIS_PORT=6379"
Environment="JWT_SECRET=替换为32位以上随机字符串"
Environment="JWT_EXPIRE_HOURS=24"
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now worklog
sudo systemctl status worklog        # 查看状态
journalctl -u worklog -f             # 查看日志
```

验证后端：

```bash
curl -s http://127.0.0.1:8089/api/auth/me -H "Authorization: Bearer 无效token"   # 应返回 401 JSON
```

> 注意：后端端口为 `8089`（application.yml 中 `server.port: 8089`）。
> 若想用 8080 之类，在 systemd 的 ExecStart 追加 `--server.port=8080`，并同步 Nginx 代理端口。

## 四、前端构建与部署

### 4.1 构建

> 前端为独立仓库，需先克隆（与后端并排放置）：
> `git clone https://github.com/YAX-J/geminix-front.git /opt/geminix-front`

```bash
cd /opt/geminix-front
npm install --registry=https://registry.npmmirror.com
npm run build
# 产物：/opt/geminix-front/dist
```

> 构建时默认 `VITE_USE_MOCK` 未定义 → 走真实 API（`/api` 前缀经 Nginx 代理到后端）。
> 生产构建**不要**设置 `VITE_USE_MOCK=true`，否则全部使用本地演示数据。

### 4.2 Nginx 配置

```bash
sudo tee /etc/nginx/conf.d/worklog.conf > /dev/null <<'EOF'
server {
    listen 80;
    server_name your-domain.com;          # 换成你的域名或服务器 IP

    # 前端静态资源
    root /opt/geminix-front/dist;
    index index.html;

    # Vue Router history 模式：非文件请求回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理（后端 8089）
    location /api/ {
        proxy_pass http://127.0.0.1:8089;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|ico|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public, immutable";
    }
}
EOF

sudo nginx -t          # 校验配置
sudo systemctl reload nginx
```

### 4.3 HTTPS（强烈建议）

有域名时用 certbot 一键签发：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

## 五、部署后验证清单

| 检查项 | 方法 |
|--------|------|
| 后端存活 | `curl http://127.0.0.1:8089/api/auth/me`（401 即正常） |
| 前端可访问 | 浏览器打开 `http://服务器IP`，出现登录页 |
| 登录注册 | 默认账号 `admin / admin123`（`InitAdminRunner` 自动创建） |
| 定时提醒 | `journalctl -u worklog | grep remind`，每天 18:00 触发 |
| 登录防爆破 | 错误密码连输 5 次 → 429 锁定提示 |
| 导出 | 周报/月报 Markdown、日报/问题 Excel |
| 图表/streak | 右栏饼图/折线图、侧栏连续打卡 |
| 标签管理 | 顶栏「🏷 标签」增删改 |

## 六、常见问题

1. **前端接口 404**：确认 Nginx `location /api/` 的 `proxy_pass` 端口与后端一致（默认 8089）。
2. **数据库连不上**：检查 `DB_*` 环境变量、MySQL 是否允许 `localhost` 连接（`SELECT user,host FROM mysql.user;`）。
3. **Redis 认证失败**：Redis 有密码时设置 `REDIS_PASSWORD` 环境变量（`application.yml` 已预留 `# password:` 注释位）。
4. **中文乱码**：数据库连接串已含 `characterEncoding=utf8`；前端 CSV 导出带 BOM；确保 MySQL 库表 `utf8mb4`（init.sql 已指定）。
5. **端口冲突**：`sudo lsof -i:8089` 查看占用；`--server.port=xxxx` 覆盖。
6. **更新部署**：后端 `mvn package` 后 `sudo systemctl restart worklog`；前端 `npm run build` 后 `sudo systemctl reload nginx`（dist 直接覆盖）。

## 七、更新发布流程（速查）

```bash
cd /opt/geminix
git pull                       # 拉取后端最新代码
cd backend && mvn package -DskipTests && sudo systemctl restart worklog
cd /opt/geminix-front && git pull && npm run build && sudo systemctl reload nginx
```
